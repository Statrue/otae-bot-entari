# 终末地蚀刻章统计功能需求文档

> 分支：`dev`
> 创建时间：2026-07-26
> 状态：需求草案，待评审
> 性质：**仅定义需求与统计口径，不含功能实现**

## 1. 背景与目标

Warfarin Wiki 提供公开 JSON 接口 `GET /v1/cn/medals`，返回《明日方舟：终末地》全部蚀刻章数据（当前实测版本 `meta.version = 1.4`，共 **140** 枚）。

本功能的目标是**基于该数据源**，提供以下能力：

1. 统计蚀刻章总数与各等级数量；
2. 统计可镀层、可升级蚀刻章；
3. 在游戏版本更新后，对比新旧数据筛选出新增的蚀刻章。

> 说明：本文档不涉及任何功能实现、命令交互或图片渲染设计，仅用于对齐需求口径，作为后续开发的依据。

## 2. 术语与数据源

- **蚀刻章**：指 Warfarin Wiki `/cn/medals` 接口返回的奖章数据。接口内中文字段写作「奖章」、`meta.type` 为 `"medal"`，本文档统一称为「蚀刻章」。
- **数据源**：`https://api.warfarin.wiki/v1/cn/medals`
- **请求头**：`Referer: https://warfarin.wiki/cn`、`User-Agent` 自定义（与现有 `WarfarinClient` 一致）。
- **响应结构**：顶层为对象，包含 `meta`（版本/语言/数量）、`data`（蚀刻章数组）、`refs`。

### 2.1 字段映射（基于实测 v1.4）

| 字段 | 类型 | 含义 | 统计用途 |
|---|---|---|---|
| `slug` | string | URL 友好标识 | — |
| `id` | string | 游戏内唯一标识（如 `achv_adv_tundra_campfire`） | **版本对比主键** |
| `name` | string | 蚀刻章名称 | 展示 |
| `groupId` / `groupName` | string | 所属蚀刻章组（部分为 `null`） | 可选分组 |
| `categoryId` / `categoryName` | string | 所属分类（8 大类） | 可选分组 |
| `categoryPriority` | int | 分类排序权重（1–8） | 排序 |
| `order` | int | 组内序号 | 排序 |
| `canBeUpgraded` | bool | 是否**可升级** | FR-2 |
| `canBePlated` | bool | 是否**可镀层** | FR-2 |
| `initLevel` | int | 初始等级 | 口径说明 |
| `maxLevel` | int | 最高等级 | **FR-1 计数依据** |

## 3. 功能需求

### FR-1　蚀刻章总数与各等级统计

**需求**：统计蚀刻章总数，以及每个等级的蚀刻章数量。

**计数口径（关键）**：每枚蚀刻章一律按其**最高等级 `maxLevel`** 归类计数。

- **理由**：可升级（`canBeUpgraded = true`）与多等级的蚀刻章，在游戏内升级后**低等级形态消失，仅保留最高等级形态**。因此总数与各等级分布都应以「最高等级」为准，才能反映玩家最终可持有的形态。
- **简化规则**：不可升级的蚀刻章其 `initLevel == maxLevel`，故无需区分，全部统一用 `maxLevel` 即可。
- 定义：`effective_level(medal) = medal.maxLevel`

**输出**：总数 + 各等级（Lv1 / Lv2 / Lv3 …）数量。

**v1.4 基线参考**：总数 140；Lv1 = 24；Lv2 = 58；Lv3 = 58。

### FR-2　可镀层 / 可升级蚀刻章统计

**需求**：分别统计以下两类蚀刻章的数量。

1. 可镀层蚀刻章：`canBePlated = true` 的数量；
2. 可升级蚀刻章：`canBeUpgraded = true` 的数量。

**可选**：附带输出这两类蚀刻章的明细清单（`name` / `slug` / 所属分类）。

**v1.4 基线参考**：可镀层 = 29 枚；可升级 = 22 枚。

### FR-3　版本对比：筛选新增蚀刻章

**需求**：当网站数据更新后，对比新旧数据，筛选出**新增的蚀刻章**。

**机制**：

- 本地维护一份「旧版本数据快照」；
- 触发对比的时机：`meta.version` 发生变化（如 `1.4 → 1.5`），或手动触发刷新；
- 以 `id` 为主键做集合差集：
  - **新增**：新数据中存在、旧快照中不存在的 `id`；
  - *（可选）移除*：旧快照中存在、新数据中不存在的 `id`；
  - *（可选）变更*：同 `id` 但关键字段（名称、等级、可升级/可镀层标记）发生变化的记录。

**输出**：新增蚀刻章列表（`name` / `id` / `categoryName` / `maxLevel`），并更新本地快照为新版本。

## 4. 验收标准

- **FR-1**：给定一份 medals 数据，能输出总数及按 `maxLevel` 分组的各等级数量，且各等级数量之和等于总数。
- **FR-2**：能正确输出 `canBePlated` 与 `canBeUpgraded` 两类的数量，与逐条筛选结果一致。
- **FR-3**：给定旧快照与新数据，能正确输出仅新增的蚀刻章；同一份数据与自身对比时，新增为空。

## 5. 非目标 / 暂不实现

- 本文档不包含功能实现、数据获取客户端、存储结构、命令交互、图片渲染等内容。
- 暂不强制要求按分类（`categoryName`）的等级分布统计（可作为后续扩展）。
